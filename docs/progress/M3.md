# Milestone 3 — Gemini and SerpApi research

Date: 2026-10-24

## Implemented

- Added strict backend research request/result contracts, graph target scores, evidence,
  candidate/requirement/cost/timing types, pending questions, and recorded activity.
- Added cycle-safe reverse traversal from the projected unpaid-bill outcome, selecting
  at most four active or explicitly conditional problem targets. In the live default
  case it ranked `bills_unpaid` and `commute_disrupted` at 27, then
  `car_unavailable` at 8. Inactive borrowing/transport/paid-repair harms are excluded.
- Added bounded SerpApi `google`, `google_maps`, and `google_maps_directions` adapters,
  source URL sanitization, request counting (including retries), per-query cache,
  observed fare parsing in cents, Central-time transit conversion, and strict
  outward/return itinerary assessment.
- Added official `google-genai` native function declarations and model-directed tool
  requests. Python executes the tools, limits searches and turns, validates candidates
  against actual source IDs and graph IDs, keeps personal permissions unknown, and
  selects at most two linked questions. Public source text is treated as untrusted.
- Added `POST /api/research/interventions` and a Next.js proxy. One read-only Nessie
  snapshot feeds one `simulate(..., actions=[])`; the response includes that snapshot,
  simulation, and a scenario/source fingerprint. Matching results are cached in memory
  for 15 minutes. No second customer was seeded and no Nessie write was made.
- Replaced Stage 3 preview with Explore: optional fictional route fields, Start/Refresh,
  truthful loading and event history, priority targets, source links, candidate status,
  uncertainty, pending questions, and errors. Stage 4 remains a future preview.

## Live verification

- Backend `.env` had all three required integration names configured; no values were
  printed or committed. The research endpoint read the existing **live Nessie**
  customer, without seeding or modifying it. The default scenario's M2 balances and
  wage-loss computations remained backend-owned.
- Gemini model listing exposed `gemini-2.5-flash`, but a generation attempt returned
  404 (unavailable for this key). A `gemini-3.8-flash` probe timed out with 504.
  `gemini-3.5-flash-lite` succeeded with an actual `search_web` function call, so it
  is the configured default. The SDK version locked for this run is `google-genai`
  1.75.0.
- Direct SerpApi probes returned five real web results and five dated Austin transit
  direction results. The direction response contained USD fare fields; its example
  geography was fictional/demo context, and no user shift or round-trip viability was
  claimed. Public source URLs were present in both probes.
- A live Next.js → FastAPI research POST returned HTTP 200 with live Nessie provenance,
  two SerpApi requests, ten evidence items, two candidates, one pending question, and
  24 recorded events in one run. A later run after stricter source validation returned
  HTTP 200 with two requests, six evidence items, one hypothesis, and one question.
  Candidate counts vary with current search/model results. No API key name/value or
  secret-bearing query parameter appeared in the inspected client JSON payload.
- The final proxy request after the explicit Gemini native function-response loop and
  strict source checks returned HTTP 200, live Nessie provenance, one SerpApi request,
  five evidence items, one **conditional** candidate, and one pending question.
- Local health succeeded on backend port 8001 and frontend port 3001; invalid research
  input through the frontend proxy returned 422. Ports 8000/3000 were occupied by
  unrelated existing processes, so this milestone's local demo uses 8001/3001.
- Browser computer-control surfaces were unavailable, so the Explore layout was
  checked by server-rendered component test, frontend build, and local HTTP/API checks
  rather than a visual browser interaction. Open `http://localhost:3001`, simulate,
  and click Explore → Start research for a manual review.

## Operating notes and limits

- Clone/install/seed as in README. Put only `NESSIE_API_KEY`, `SERPAPI_API_KEY`, and
  `GEMINI_API_KEY` in ignored `backend/.env`, then `npm run dev`. If default ports are
  busy, start FastAPI from `backend/` on 8001 and Next.js with
  `BACKEND_URL=http://127.0.0.1:8001` on 3001. No new seed or reset is needed for M3.
- Ordinary tests make zero live provider calls. Explore starts a bounded live pass:
  six SerpApi HTTP requests maximum, eight on explicit Refresh; three Gemini research
  turns plus extraction, 85-second research deadline, per-call timeouts, and 15-minute
  in-memory result cache. Actual provider billing/free-tier accounting is unknown;
  the final measured UI proxy runs used two SerpApi requests each.
- A search listing is not proof of eligibility, employer approval, bill deferment,
  appointment, fare for this specific route, or a feasible return trip. Missing route
  endpoints/times keep transit conditional. Gemini and SerpApi can return partial or
  no-results states; the UI never fabricates a provider option to fill space.
- M4 will bind answers to requirements, define dated action effects, run combinations
  through the deterministic simulator, and compare actual mitigated outcomes. M3 did
  not implement these tasks or pass nonempty `actions` to M2.
