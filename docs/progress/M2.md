# Milestone 2 — Crisis simulation and consequence graph

Date: 2026-10-24

## Implemented

- Added a pure, typed `simulate(snapshot, scenario, actions=[])` engine using integer
  cents and explicit dates. Recovery actions are an empty extension point only.
- Added `POST /api/simulations/crisis`, returning the exact read-only customer snapshot
  used alongside its simulation result.
- Added explicit weekday shift dates, pay-period mapping, 80%-estimated take-home loss,
  baseline/crisis event construction, 31 inclusive daily points, and source timestamps.
- Added separate unconstrained funding-gap and constrained bill-allocation ledgers.
  Paychecks process first; essential bills precede discretionary bills; ID breaks
  same-day ties; partial/unpaid obligations are retained rather than falsely deducted.
- Added all 14 locked problem nodes and 17 stable edges with status, activation date,
  evidence, amount, source, and truthful conditions.
- Added an animated React Flow graph with node inspection and reduced-motion behavior.
- Added normal-versus-crisis line series, a dated event ledger, projected unpaid-bill
  cards, scenario reruns, and a collapsible view of the complete banking context.
- Preserved disabled placeholders for research, questions, and recovery plans. No Gemini,
  SerpApi, solution discovery, action scoring, payment, borrowing, or Nessie mutation was
  added.

## Financial assumptions

- Scenario calendar: `America/Chicago`; default start is the loaded snapshot date.
- Work: Monday–Friday, five eight-hour shifts, 40 gross hours weekly.
- Take-home multiplier: 80%, visibly labeled as an estimate.
- Default untreated crisis: two missed shifts, $0 transport, $0 borrowing, no debt
  payment, no late fee, and the repair quote unpaid/deferred.
- The quote affects graph exposure only. It creates a repair event only if a future caller
  explicitly supplies `repair_payment_status=paid` with a date.
- The 30-day horizon includes both start and end dates, producing 31 daily points.
- Monthly historical averages remain display context and never become daily debits.

## Required numeric example

The isolated unit fixture uses a $310 opening balance, one $640 projected paycheck, two
missed $20/hour shifts at the 80% estimate ($256 loss), a $900 essential bill after that
payday, and an unpaid $400 quote:

```text
Raw crisis ending balance = $310 + $640 - $256 - $900 = -$206
Constrained allocation     = $694 funded, $206 projected unpaid, $0 cash
```

Both results passed automated tests. The wage loss appears only on the covered future
payday, and the quote creates no bank event.
