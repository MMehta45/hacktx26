## What changed

The old request accepted `affected_shift_count`, `affected_shift_dates`,
`repair_delay_days`, `repair_payment_status`, and `repair_payment_date`. Those caller-
selected outcomes are removed. The request now accepts `breakdown_date` and a default
07:00 local breakdown time. The engine creates every scheduled weekday shift, decides
attendance from vehicle availability at 08:00, and maps earned wages to the correct
following-Friday paycheck.

The forward income projection now maps October 19–25 to October 30, October 26–November 1
to November 6, and November 2–8 to November 13. The October 30 paycheck is already earned
at the frozen October 24 snapshot and remains $640 after the October 26 breakdown.

Repair evaluation runs after each day's shift, payroll, and bills. It requires the full
quote plus cash reserved for essential bills through the next reliable payday. Paying
restores the car that day but never retroactively changes the morning shift. If the
policy cannot fund the quote, no repair debit is emitted and the vehicle stays unavailable.

Research receives derived missed-shift dates, impacted payroll records, and repair
funding details. Transit calls still obey the existing provider budget. The remote-work
candidate/question now names the calculated number and dates of at-risk shifts.

## Seed and migration

No reseed is required. Existing deterministic fixture and Nessie seed deposits are
already thirteen weekly $640 Friday transactions and remain historical facts. Only
future forecast period mapping changed. Normal API requests never alter seeded data.

If a developer independently has an older or manually altered demo account and chooses
to rebuild it, the controlled destructive command is:

```bash
npm run seed:customer:reset
```

That command is optional for this milestone and was not run during verification.

### Local stale-process regression

The first manual port-3001 demo paired the updated frontend with an older non-reloading
backend still occupying port 8001. FastAPI correctly rejected `breakdown_date`, but the
proxy converted its validation array to `[object Object]`. The stale pair was replaced
with matching Build 03.5 processes, and all proxy routes now normalize FastAPI validation
issues into readable `field: message` text. The exact browser request was replayed through
port 3001 and returned schema 2 in live Nessie mode.

## Remaining limitations and Build 04 boundary

The model assumes fixed weekday attendance, no paid leave, no partial shifts, and
same-day vehicle restoration after a full payment. It does not infer taxes beyond the
80% estimate, partial repair financing, transportation, remote work, borrowing, or bill
extensions. The bill-protective policy is conservative rather than optimized. Build 04
can consume the structured shift/payroll/repair outputs to compare explicit recovery
actions; none are implemented here.
