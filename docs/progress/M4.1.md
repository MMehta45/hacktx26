# Build 04.1 — Recovery, transit, and mechanic corrections

Date: 2026-10-25

## Root cause and fixes

The local recovery 404 was caused by stale processes. Port 8000 belonged to another
repository and exposed only `/api/v1/*`; the hacktx26 backend on 8001 was a Build 03 process
without recovery routes. The current code did register `POST /api/recovery/sessions`.

- Added API version/capability metadata to `/health`.
- Added explicit proxy error codes for missing route, missing session, invalid payload, and
  unavailable backend.
- The frontend now discards local storage only for a confirmed stale session 404, then
  creates a real new session. It preserves actionable errors for all other failures.
- Restarted only the stale hacktx26 processes; the updated fixture-mode app is available at
  `http://127.0.0.1:3001` with FastAPI at `http://127.0.0.1:8001`.

## Transit audit

A bounded live SerpApi request used the documented Central-time Unix timestamp
`arrive_by:1793019000` for October 26 at 07:50. SerpApi echoed that parameter but returned
12:20–12:40 and 21:34–21:50 routes. Those results are now labeled as not honoring the time
constraint and cannot protect a shift.

Usable provider fields were confirmed as:

- `directions[].start_time`, `end_time`, `duration`, `cost`, and `currency`
- `trips[].travel_mode`, `title`, `duration`, and `distance`
- transit `trips[].start_stop` and `end_stop`, including name and time
- top-level `places_info[]` for resolved endpoint comparison

The live normalized outbound now reports 21 minutes, 7 walking minutes, route 5, the real
boarding/alighting stops, and a provider-observed $1.25 fare. Fare provenance is retained as
the SerpApi directions cost field. The itinerary remains financially unusable because the
provider did not honor the requested time. No official fare fallback was needed because a
numeric provider fare was present.

## Remaining limitations

- SerpApi currently echoes but does not reliably honor the requested transit time for this
  route. Those itineraries remain raw evidence and never become quantified actions.
- Provider direction responses contain local times without an explicit service date; the
  requested date is retained with a separate time-honored check.
- Recovery sessions remain in process memory and are recreated after a backend restart.
- Browser automation was unavailable, so UI rendering is covered by component tests,
  production build, and live HTTP/proxy checks rather than an automated click recording.
