## Implemented

- Added `CustomerSnapshot` schema version 1 with normalized customer, account,
  transaction, category, bill, income forecast, scenario, and provenance records.
- Added a deterministic Maya Torres fixture with 24 purchases, 13 historical deposits,
  category summaries, a $310 balance, and dated synthetic obligations.
- Historical fixture deposits and purchases reconcile to each other. User-entered gross
  wage remains an independent future forecast: 8× hourly rate per shift and 40× weekly.
- Added `GET /api/customer/snapshot` with validation for display name, wage cents, and
  repair quote cents.
- Added a backend-only Nessie client for customers, accounts, merchants, purchases,
  deposits, and readable bills. Errors do not include authenticated URLs or response
  bodies.
- Added `npm run seed:customer` and `npm run seed:customer:reset`. The manifest is saved
  under ignored `backend/.local/`; stable descriptions make normal reruns idempotent.
- Added four navigable frontend stages. The snapshot shows accounts, balance, categorized
  history, monthly approximations, bills and source, historical-deposit count, and gross
  payday forecasts.
- Graph, agent activity/question, and recommended-plan views are explicitly labeled as
  previews and make no claims that analysis, research, or recommendation occurred.

## Nessie status and manual configuration

No `backend/.env` file was present during implementation. Therefore:

- No real Nessie customer, account, merchant, bill, purchase, or deposit was created.
- No Nessie seed idempotency or live readback is claimed as passed.
- The verified UI path used the clearly labeled local fixture.

To complete live verification, put `NESSIE_API_KEY` directly in ignored `backend/.env`,
run `npm run seed:customer` twice, confirm the second run reports reuse, start the app,
and confirm the dashboard badge says “Live Nessie sandbox.” Do not paste the key into
source, documentation, issues, or logs.
