# Build 04.3 Critical Integration Corrections

Date: 2026-10-25

## Corrections

- Transit normalization now distinguishes provider-observed fares from the official
  published CapMetro standard fare fallback. Missing fare is never treated as zero; late or
  otherwise time-invalid itineraries remain unknown-cost and cannot protect a shift.
- Qualification remains per shift/day. A valid outbound and return pair can produce a
  dated action for only the covered shifts rather than requiring all affected shifts.
- Research income-preservation candidates are merged into the existing remote-work action
  family, retaining evidence and unknowns instead of creating a duplicate 21-shift lead.
- Explore evidence remains available as `actionable_resources` in Plan even when its
  candidate is not financially quantified. Each resource retains evidence IDs, URL, action
  association, limitations, and relevant transit date.
- Research leads now expose their exact missing information. Manager and landlord approvals
  remain user/third-party facts and produce drafts; transit timing/fare can be researched;
  mechanic work requests ask for a written quote rather than asserting a review-derived price.
- Yes/no questions now have an explicit `not_yet` answer. It maps to unresolved or pending
  requirements, preserves conditional plans and drafts, and supports later reversal without
  treating uncertainty as rejection.
- Google Maps Directions remains the transit authority (`travel_mode=3`); valid timing with
  missing fare is retained as a lead or receives explicitly published-fare provenance, never
  a zero-dollar assumption.

## Transit fixture verification

The regression fixture includes an early valid route with no provider fare and a separate
late route. The valid route receives a `125` cent `official_published` CapMetro fare with
explicit provenance; the late route remains `unknown` and `transit_time_constraint_honored` is
false. The existing simulator action conversion still requires valid outbound and return
evidence, so no route is forced into the optimizer by relaxing timing rules.

## Targeted timing diagnostic

On 2026-10-25, one bounded live Google Maps Directions request used `arrive_by:1793019000`,
which is `2026-10-26T07:50:00-05:00` in Austin. SerpApi returned five transit alternatives,
all arriving between 12:10 PM and 12:40 PM. Normalization retained every alternative and
correctly rejected each as late. The timestamp conversion and Austin timezone are correct;
the provider result did not honor the requested time. Provider-returned links also did not
reliably encode the requested time, so the app now emits a transit-mode/endpoints link with a
clear limitation rather than claiming the click-through page preserves the verified schedule.

Unknown remote-work answers now create an inquiry draft asking the manager whether temporary
remote work is permitted and what equipment/access is required, without crediting any wages.

## Final timing correction

Outbound Maps requests now target the actual 08:00 shift start (the provider itinerary's
final walking leg is included in that arrival). Return requests target 16:15, a 15-minute
post-shift buffer. Regression coverage asserts Austin-local ISO values for both targets.
